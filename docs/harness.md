# The accuracy harness

The accuracy harness is the judge of right and wrong for idtrack. Every query has an expected answer taken from Ensembl's own data (the GTF files of every release, the archive BioMarts, the history tables of the core database), never from idtrack: a change of idtrack changes its answers, so earlier answers cannot be the judge. A change of idtrack's answers is accepted only when the harness lists no answer that went from right to wrong (rule [`truth_judges`](rules.md#truth_judges)). The [regression corpus](corpus.md) says *whether* an answer changed; this harness says whether it is *right*. Every benchmark family extends it ([methods](methods.md#the-families)).

Code: `idtrack_reproducibility.harness`. Data: the truth store `<truth>/<organism>/`, the query sets `<harness>/queries/<organism>/`, the runs `<harness>/runs/` (locations of the configuration). The current results of the reference tree `d4c2dda` are in `results/harness/d4c2dda/<organism>/`.

## Running it

```
# every shard as a job of the configured runner, then a merge job that scores (pig: 8 shards)
python -m idtrack_reproducibility.harness.score --clone <tree checkout> --graph <graph file> --organism sus_scrofa \
    --out <harness>/runs/<tree>/sus_scrofa/kinds --submit 8
# in one process (inside a job: the graph of the reference tree needs the memory of the configuration's [jobs.memory_gb])
PYTHONHASHSEED=0 python -m idtrack_reproducibility.harness.score --clone <tree checkout> --graph <graph file> \
    --organism sus_scrofa --out <folder>
# a quick look: the first 60 queries of each kind (most of the time is loading the graph)
python -m idtrack_reproducibility.harness.score ... --limit 60
# compare two runs: per-kind change and every query right in a and wrong in b (exit status 1 if any);
# every answer whose outcome moved, with the judge (rule) of its line, in --moved
python -m idtrack_reproducibility.harness.compare_scores <run a> <run b> [--variants] [--out changes.tsv] [--moved moved.tsv]
# stored answers scored again (other sets, or the judge before its corrections) without touching them
python -m idtrack_reproducibility.harness.score ... --out <run with the answers> --merge [--sets v1,v2 | --judge published] \
    --scores-to <folder>
```

- `--clone` is the checkout of a tree of the configuration (`[trees.<name>] source`) and `--graph` its graph of the organism (`[trees.<name>.graphs]`); with `--submit` the shards run in the tree's own Python (`[trees.<name>] python`) with this package on its path, through `idtrack_reproducibility.jobs` (`<name_prefix>harness_<organism>_<i>` and `..._merge`; `--tag` names them otherwise), and every job has `PYTHONHASHSEED=0` and `IDTRACK_ENSEMBL_ACCESS=https`. A graph file is linked into `<out>/repo/` under its own name, so nothing is written beside the original; a folder is used as the local repository as it is. `--release` gives the snapshot when the graph's name has no `max<release>`.
- The graph is loaded through the tree's public api (`idtrack.API(local_repository=...).build_graph(organism, snapshot_release)`), then `gc.freeze()`, so that garbage-collector pauses over the loaded graph are not counted as query time. Each query is one `API.convert_identifier(id, from_release, to_release, final_database, strategy)` call with a time limit (`--timeout`, default 30 s).
- Reading the answer is in one function, `score.targets_of`: the ids of `target_id`; nothing when `no_corresponding` or `no_conversion` is set; with a `final_database`, nothing when `no_target` is set or the answer is in another database (a fall-back to Ensembl ids is not an answer in the requested database). It also accepts a per-target list of records (`id`, `database`, `no_target`/`fallback`). A tree that changes the result format adapts this function and nothing else; the trees with `API.convert` (`71690ab` on) are asked through the common machinery's adapter, which reads them the same way ([F0](families/f0.md)).
- `PYTHONHASHSEED=0`: ties that a tree breaks by set order come out the same in every run, so two runs differ only by the code and the graph.
- Results are appended per shard (`<out>/results/shard_<i>_of_<n>.jsonl`). A query belongs to shard `crc32(qid) % n`, and a shard skips every query that has a result in any shard file of the folder, so a resubmission (with any number of shards, or after a new set is published) runs only what is missing. `--merge` scores whatever is there and reports the queries without a result (`n_missing`).
- `compare_scores` exits with status 1 when there is a regression (right -> wrong, right -> error); right -> timeout and right -> undetermined are listed too and need a word of explanation.

Outputs in `<out>`: `scores.tsv` (kind, variant, n, right, wrong, undetermined, timeout, error, rate, 95 % Wilson interval; variant `*` is the whole kind, the others are `<strategy>,<from|default>`), `outcomes/part_0_of_1.parquet` (the record: every query with the call, the truth, the answer and the verdict, in the columns of every family's scoring, [the record](records.md)), `outcomes.tsv.gz` (derived from it: every query's outcome, reason, answer, seconds and the judge of its line; what `compare_scores` and `travel-report` read), `wrong.tsv` (query, expected, the wider set if any, got, reason, judge), `errors.tsv`, `timeouts.tsv`, `undetermined.tsv`, `run.json` (the record's version; the commit of the checkout that answered, read from the answers' load records, and whether it had local changes; graph file, size and time, query sets with sha256, time limit, excluded lines, the copies checked, load time, files the load wrote into the repository folder, total query time).

**rate = right / (right + wrong + error).** `undetermined` (Ensembl's own data leave the answer open) and `timeout` (not answered within the limit) are reported apart and never counted as right or wrong.

## The query sets

`<harness>/queries/<organism>/<set>.jsonl.gz` with `<set>.manifest.json` (counts per kind, sha256, the truth files used). Built by `make_queries --organism <o> --set <name> [--kinds ...]`, seed 20261112, each kind with its own random generator over a sorted population, so that adding kinds never changes the sample of another. **A published set is never rewritten** (the module refuses to overwrite a set or to publish a kind twice); new kinds go into a new set, and `score` scores every published set by default. A change of the truth of published queries is published as a **revision set** (its manifest has `revises`, naming the sets and their sha256): it holds only the lines that change, under their published `qid`, and `score` takes the line of the latest set for a `qid`; the query is asked once, and its stored answer can be scored under either truth (`--sets` with the sets before a revision gives the earlier one). Sets are ordered by their number (`harness_lib.set_names`: `v10` after `v9`). Scores of the same set are comparable across trees and graphs.

New sets do not contain them (`harness_lib.NOT_A_DATABASE_OF`). Lines a correction marks `excluded` are left out the same way (`projected_hgnc`: 4 mouse lines).

## The query line and the scoring rules

A query line: `qid`, `kind`, `id`, `from_release`, `to_release`, `final_database`, `strategy`, `rule`, `cmp`, `expect`, `broad`, `locus`, `note`. A line of a revision set of rule `judge_copies_apart` also has `apart` (the copies on patches and alternative loci that the answer must report apart). Lines revised by the corrections of the judge name them (`revised_by`) and may have `locus_mapped` (the query's place mapped to the target's assembly, or `unmapped` with the reason), `exceptions` and `locus_projected` (places on haplotypes, patches, alternative loci and Y PARs put on the reference sequence), `core_places` (genes the GTF lacks placed from the core), `support` (name sources per expected gene), `spellings` (spellings of one value) or `excluded` (the reason the line is left out).

Scoring rules (`score.score_one`, the one function every family's scorer calls):

- `set`: right when `best` returns a non-empty subset of `expect` (or nothing when `expect` is empty), and when `all` returns exactly `expect`.
- `set_exact` (used when the right answer is several genes, e.g. a name that several genes carry at that release): both strategies must return exactly `expect`.
- `broad`: a superset that Ensembl's data also allow (see [the kinds](#the-kinds)); an answer that is not right but lies within it is `undetermined`.
- `locus` (only with an empty `expect`, i.e. Ensembl's history has no successor): a returned gene outside `broad` that overlaps the query gene's place (GTF coordinates, same sequence and strand) makes the answer `undetermined`; a returned gene elsewhere makes it `wrong`. With `locus_mapped` the query's place is taken on the answer's assembly ([places across assemblies](#places-across-assemblies)); a place that could not be mapped (no chain, or under half of it aligned) leaves the answer `undetermined` with the reason. With `exceptions`, places on haplotypes, patches, alternative loci and Y PARs, of the query and of every returned gene, are compared on the reference sequence; a place that cannot be put there leaves the answer `undetermined`. With `core_places`, a returned gene that the GTF of the target release lacks is placed from the core's tables.
- `apart` (rule [`judge_copies_apart`](#rule-judge_copies_apart)): an answer that is right by the rules above must also list every gene of `apart` in `alternative_locus_genes` (stored per answer as `apart`); if it does not, it is `wrong` ("copies not reported apart"). An answer stored by a tree that has no such list keeps its outcome with the reason "copies not checked", and `run.json` counts them (`copies_apart`: `expected`, `checked`, `unchecked`).
- `support` (rule [`support_ranks_shared_name`](rules.md#support_ranks_shared_name)): a `best` answer that is a non-empty proper part of a `set_exact` expectation whose genes all have strictly more support than every expected gene left out is `undetermined`.
- `spellings`: the spellings of one value count as one.
- `cmp`: `versioned` (returned gene ids are compared with their version, which is the GTF version at the target release), `base` (without version; releases whose GTF has no versions: pig before 77), `exact` (external ids, as BioMart writes them).

Every scored line names its judge in `outcomes.tsv.gz`, `wrong.tsv` and `undetermined.tsv` (`rule`: `published`, or `revised:<corrections>`).

### How the history is read

`make_queries.Truth`: mapping sessions are ordered by their old release and creation date; from a gene id at release a, each session between a and b maps the id to its successors (ids without an event in a session continue unchanged; an event to nothing ends the line). **Strict** walk: where a session maps the id to itself, only itself is followed (the id lives on; this is REST's `possible_replacement` semantics); otherwise all its successors. **Broad** walk: all successors, also branches that left while the id lived on. Only ids that exist at b (GTF of b) are kept. The backward walk is the mirror image. With living ids (rule [`id_lives_on`](rules.md#id_lives_on), correction `living_ids`) an id present in the GTFs on both sides of a session is kept; with returned ids (rule [`resurrection`](rules.md#resurrection)) an id that Ensembl retired and brought back is one gene throughout and what is reached only through its return goes to `broad`. A session is crossed where its effect appears in the GTFs (correction `sessions_effective`); mislabelled sessions (pig 106 -> "104", human 114 -> "114") are placed by their old release, which is right in both.

### The check against REST

`check_truth`, on the records of `rest/` (an earlier sample plus a seeded sample of 1,500 retired ids per organism and their chains, `fetch_rest`): for every id with a REST record that is not current, REST's chain of `possible_replacement` followed to ids of release 115 is compared with the strict walk from the id's last release. Pig: 3,916 of 3,916 equal; mouse 2,050 of 2,051; human 3,175 of 3,178 (8 REST chains incomplete); rhesus 1,839 of 1,839; cynomolgus 1,500 of 1,500 (`<truth>/<organism>/check_rest.json`). The four differences are ids whose REST answer has a successor the walk lacks (e.g. human `ENSG00000248671`, absent from the GTFs of 111-115 although no event of the release-115 core retires it; REST answers for release 116). The check tests the reading, not the history: both read Ensembl's events.

## Rule `version_newer_than_graph`

Rule [`version_newer_than_graph`](rules.md#version_newer_than_graph) refines "a version that never existed has no answer": a version higher than the last version of an id that is still active at the graph's last release may belong to a release newer than the graph and is answered with the id's gene, flagged; every other unknown version (lower, in a gap, or of a retired id) is answered with nothing (rule [`unknown_version`](rules.md#unknown_version)). The kind `nonexistent_version` of the first sets holds only queries of the first sort (a current id, largest version + 37) with the expectation "nothing", which the rule reverses. Its lines stay in the published sets and it is still scored (0 % by design), but it is no part of the acceptance; the two kinds `version_newer_than_graph` and `version_unknown` replace it (sets `v2` of pig and the macaques, `v3` of mouse and human; `make_queries --kinds version_newer_than_graph,version_unknown`). Truth: the versions of every gene id in the GTF of every release (`gtf/genes_<release>.tsv.gz`); the graph takes its versions from the core `gene` tables of the same releases. Pig GTFs before release 77 carry no versions, so for pig the "gap" and "lower" queries are limited to ids born at 77 or later (one query); "retired" needs only the last version, which is known for every id retired at 77 or later.

## Rule `judge_copies_apart`

Rule [`copies_apart`](rules.md#copies_apart) takes the copies on patches and alternative loci out of an answer that holds a gene of the reference sequence and reports them apart (`alternative_locus_genes`); rule [`judge_copies_apart`](rules.md#judge_copies_apart) makes the judge say the same in the kinds whose truth comes from Ensembl's history and old name tables. The kinds drawn from BioMart's current name tables were written so from the start (`& primary` in `make_queries.build`).

**What the revision does** (`make_queries --organism <o> --set <new> --copies-apart`): it reads the latest published line of every query and revises a line when all of this holds: it expects Ensembl gene ids (no `final_database`); the GTF tables of its target release mark patches (the release has a `chr_patch_hapl_scaff` GTF file: human 82 to 116, mouse 82 to 102; the target releases that occur among such lines are 103 and 115 for human, 92 and 102 for mouse); its expected set holds at least one gene of the primary sequence **and** at least one gene on a patch or alternative locus there. The revised line keeps its `qid`, query, `cmp`, `broad` and `locus`; `expect` becomes the genes of the primary sequence, `apart` the others; `rule` `set_exact` becomes `set` when one gene is left (it was `set_exact` only because several genes were expected). The scorer takes a later set's line in place of the earlier line with the same `qid`, stores the copies an answer reports apart, and checks a right answer for the expected copies (`apart` in [the scoring rules](#the-query-line-and-the-scoring-rules)).

**What it leaves as it is.** Every line whose expected genes are all primary or all copies (a query for a gene that lies on a patch still expects that gene), every line with a `final_database`, every line of pig, rhesus, cynomolgus and mouse (none has an expected set with both sides at a release whose GTF marks patches: `--copies-apart --dry-run` prints empty counts for them, so no set was published), and every line whose target release is before 82 (the GTF of those releases does not tell patch and haplotype genes from the primary sequence; [limits](#limits)). Human: set `v4`, 284 lines. In the current human scoring every expected list of copies is checked and no answer lacks an expected copy (`copies_apart` in `run.json` of `<harness>/runs/d4c2dda/homo_sapiens/kinds/`: expected 284, checked 284; of `.../travel/`: expected 510, checked 510; no wrong answer has the reason "copies not reported apart").

## Rule `name_before_synonym`

The lines of `synonym_to_gene` were drawn from BioMart's synonym table, leaving out the strings that are a display name, without asking whether the string is a name in another name table. Rule [`spelling_of_release`](rules.md#spelling_of_release) reads a string that a database writes exactly as a gene's name as that name, before any synonym ([`names_before_synonyms`](rules.md#names_before_synonyms)); rule [`name_before_synonym`](rules.md#name_before_synonym) makes the judge follow it.

**The rule** (`make_queries.name_before_synonym`, one function for both uses). A name is the display name of a gene or its value in a name table of BioMart at the release asked about (`make_queries.exact_names`: HGNC symbol, MGI symbol, UniProt gene name, NCBI gene label, WikiGene name), compared exactly as written. Where the genes of the primary sequence that carry the string of a `synonym_to_gene` line as a name are not empty and differ from the genes the line expects (the name of a gene that is not among them, or the name of only some of them, since names are tried before synonyms at each step), the line expects the genes of the primary sequence that carry the string as a name, alone; a string that is the name of exactly the genes a line expects, or of none, changes nothing; `rule` is `set_exact` when they are several and `set` when one (as for every name kind); `broad` (the genes that carry the string in any source, the synonym table among them) is kept, so an answer with the synonym's genes is `undetermined` (where a line had no `broad` because its expected genes were all the genes with the string in any source, they become its `broad`, as `build` gives it). `make_queries.build` applies the rule when a set is generated; `make_queries --organism <o> --set <new> --names-first` applies it to the latest published line of every query and publishes the lines that change as a revision set (nothing is written when none changes). The generator and the revision agree: for the five organisms `build` gives, qid by qid, the published lines with the revision applied.

## The corrections of the judge

Rule [`judge_corrections`](rules.md#judge_corrections): the judge is corrected where it is wrong, with evidence that does not come from idtrack. A reading of every wrong answer of the harness found the truth wrong for some lines and unable to decide for others, and the places across assemblies widened what it can decide. Every correction rests on Ensembl's, BioMart's, the GRC's, VGNC's or UniProt's own files, never on idtrack's answers. Nothing published is rewritten: each correction is a revision set (`make_queries --organism <o> --revise <correction>`, or `--revise all` for every one in order), holding only the lines it changes under their published `qid`, with a manifest naming the sets it revises (`revises`), the correction (`correction`), what it does and why (`revision`, the docstring of its `rev_<correction>` function) and a field `judge` that marks it as a set of the corrected judge. Each revised line lists the corrections that changed it (`revised_by`). The corrections read the lines as the earlier ones revised them, so the order is fixed (`make_queries.REVISIONS`); every correction leaves a line it already revised as it is, so `--revise all` run again publishes nothing. A set generated now (`build`, `build_travel`) carries the corrections (`apply_revisions`).

**Two judges.** `score --judge published` scores with every set but those of the corrected judge (the judge as first published); the default scores with every set. `outcomes.tsv.gz`, `wrong.tsv` and `undetermined.tsv` name the judge of every line (`rule`: `published`, or `revised:<corrections>`); `compare_scores --moved <file>` lists every answer whose outcome moved between two scorings with the judge of both, and prints the moves counted by judge. The results of this repository are under the corrected judge.

Each correction, in the order published (`make_queries.REVISIONS`), with its evidence and its revision sets (the set and its lines per organism; [the query sets](#the-query-sets) has the kinds):

1. **`swissprot75`: BioMart 75's Swiss-Prot by accession.** At release 75 the BioMart attribute `uniprot_swissprot` is the entry name (`_attributes.txt` of the 75 archive: `uniprot_swissprot` is `display_label_1074`, `uniprot_swissprot_accession` is `dbprimary_acc_1074`); from 77 on the attribute holds the accession. ## The judge following idtrack's decided rules

Rule [`judge_follows_rules`](rules.md#judge_follows_rules): where a rule decided for idtrack after `71690ab` changes what a line asks or expects, the harness follows the rule, as family E's `decided` judge does. The mechanism is that of the corrections (`make_queries --organism <o> --revise <name>`, `make_queries.REVISIONS`, one revision set per correction and organism, nothing published is rewritten), with the manifest's `judge` `rules` (`make_queries.RULES_JUDGE`); the judge `published` leaves them out with the corrections (`harness_lib.REVISED_JUDGES`). Each follows the rule as idtrack's tree that builds it states it, and reads the truth's own files:

1. **`missing_values`: rule [`missing_values`](rules.md#missing_values).** A line whose string stands for a missing value (pandas' own list of missing values, read from pandas, and `NaT`, `unknown`; any letter case, white space) asks for no gene: the harness's lines carry no source database, so the rule refuses it. The line is left out (`excluded`, with the reason); family E measures the refusal. Set: pig `v14` 3 (`synonym_to_gene` of the string `N/A`, a synonym BioMart gives one gene).
2. **`lower_case_symbols`: rule [`single_case_symbols`](rules.md#single_case_symbols) for strings written entirely in lower case.** As `capitals_mgi` does for capitals: in an organism whose nomenclature authority writes symbols in mixed case (the source of most display names in BioMart's gene table writes more than half of them with a small letter: MGI; `make_queries.mixed_case_symbols`), a string in lower case that is no exact symbol and is, without letter case, the symbol of exactly one gene of the primary sequence expects that gene; the genes it expected go to `broad`. Set: mouse `v20` 3 (`narf`).
3. **`stray_punctuation`: rule [`stray_punctuation`](rules.md#stray_punctuation).** A string with punctuation that ends a sentence at its end, or quotes around it, asks for the identifier without them: the line expects the genes that carry the string, with or without the punctuation, as a name at the release asked about, else as a synonym (genes of the primary sequence); the genes it expected go to `broad`. Set: mouse `v21` 2 (`alpha-1 antiproteinase,`: BioMart's synonym carries the comma).
4. **`par_shared_names`: rule [`par_shared_names`](rules.md#par_shared_names).** A line asked by a name whose expected set holds a gene in a pseudoautosomal region of Y (Ensembl's assembly exceptions of the target release, type PAR) together with the gene of X its place equals (projected by its offset, GTF places) expects the X gene, the Y copy reported apart (`apart`). Set: human `v18` 198 (`name_ambiguous_to_set` 117, `ncbi_to_gene` 52, `synonym_to_gene` 20, `refseq_to_gene` 4, `uniprot_to_gene` 3, `name_old_to_current` 2).

These are every line the trees that build the rules were measured to move from right to wrong on the harness's published sets (`d4c2dda`'s answers right, the new tree's wrong, only because the judge expected the old rule): pig 3, mouse 5, human 198 (one more human line, `name_changed_gene` `XGY2` from 105, moves from right to undetermined: within its `broad`, no revision needed). The decided rules `par_y_ids` and `lrg_answers_gene` change no line of the harness (it asks no `_PAR_Y` id and no LRG id).

## Places across assemblies

The `locus` rule judges an answer to an id that Ensembl's history ends (no successor) by place: a returned gene that overlaps the query gene's place on the same sequence and strand is `undetermined`, one elsewhere is `wrong`. The place is mapped to the answer's assembly through Ensembl's own assembly chain files and the rule is applied as on one assembly (correction `places`).

## The travel matrix

The published kinds ask about some twelve releases per organism; history travel is idtrack's reason to exist, so the travel matrix judges it over every pair of releases of the graph's window.

**The set** (`make_queries --organism <o> --set <next> --travel`, `build_travel`; the manifest's `travel` holds the strata and their ids). Gene ids of the window are put in strata by their history (`travel_strata`, from the GTF and the strict walk with living ids): `unchanged` (present at every release), `born_late` (present at 115, born after the first release), the retired ids by their fate from the last release (`renamed`, `merged`, `split`, `retired_none`; `retired_branch` where it occurs), and one stratum per assembly handoff (`handoff_<last>_<first>`: present on both sides; ids of no other stratum). 50 ids per stratum (`TRAVEL_IDS`, seeded), each asked from up to 5 releases where it exists (`TRAVEL_ORIGINS`, spread evenly over its releases, first and last included) to every release of the window, forward, backward and in place; `best` for every id, `all` for every other id, and for every sixth id a final database of a name (`HGNC Symbol` for human, `MGI Symbol` for mouse, `UniProtKB Gene Name` for the others) at the target releases that have a BioMart table. Plus 150 display names of one gene at the oldest BioMart release (pig, human, mouse, rhesus 75; cynomolgus 105), travelled to every later release (`travel_name`). The truth is that of the history kinds under the corrected judge: the strict walk with living ids (`expect`), the broad walk with returned ids (`broad`), copies apart, the `locus` rule with the place mapped across assemblies and projected from haplotypes and patches, and for the names the corrections `split_name_set` and `names_broad` (the travel names of pig, mouse and rhesus were published with `set_exact` where Ensembl split the one gene, and without `names_broad`; the revision sets after their travel sets make them `set` and widen `broad`, as for human, whose travel set `build_travel` already wrote with `set`). Lines: pig 192,250 (set `v11`), mouse 204,556 (`v13`), human 201,448 (`v12`), rhesus 193,596 (`v10`), cynomolgus 59,400 (`v7`; window 91 to 115, one handoff); the revision sets follow each.

**Run** on `d4c2dda`, asked (not rescored): `score` with the travel set and its revision sets (8 shards and a merge), then `travel_checks` and `travel_report`. The answers are in `<harness>/answers/d4c2dda/<organism>/travel/` (with `checks/`), the current scoring in `<harness>/runs/d4c2dda/<organism>/travel/`.

**The checks that need no truth** (`travel_checks`, on the same answers; queries the matrix lacks are asked through the tree; every violation asked again with `explain=True`, its paths in `checks/violations.jsonl`): identity (an id asked at a release where it exists, to that release, answers itself: every such line), composition (where R1 -> R2 answers one gene h, h travelled R2 -> R3 gives what R1 -> R3 gives: 3,000 seeded triples), return (where R1 -> R2 answers the id itself, R2 -> R1 answers itself: 3,000 pairs). Each composition violation is then read against Ensembl's history, every leg judged by the travel truth (`checks/violations_truth.tsv`). ### What stays wrong

Each wrong answer of the kinds has a cause, given by the cause classifier on its explained path (`idtrack_reproducibility.families.causes`; classes and counts in [F0's causes](families/f0.md#causes)):

- **NCBI gene labels as NCBI gene ids** (`old_gene_to_db` to `EntrezGene` at releases before 88; every organism but cynomolgus, whose window starts at 91): the answer holds the NCBI symbol beside the number, because Ensembl gives the label rows and the accession rows one database name there (rule [`one_kind_per_database`](rules.md#one_kind_per_database), decided).
- **Bridges** (`retired_none`, `reverse_absent`, `cross_assembly`, `name_changed_gene`, some `name_old_to_current`, and the travel matrix): see above.
- **miRBase names** (pig and rhesus: `name_unique_to_gene`, `separator_variant`, `case_variant`, `name_ambiguous_to_set`, `name_old_to_current`; rhesus `name_changed_gene`; a few human `name_unique_to_gene` and `separator_variant`): miRNA genes whose display name comes from miRBase, which the graph does not include (rule [`mirbase_genes`](rules.md#mirbase_genes), decided).
- **RFAM family labels** (human `name_ambiguous_to_set`, `name_unique_to_gene`, `name_old_to_current`; mouse `name_changed_gene`, `name_old_to_current`): a family label read as a name of every gene of the family (rule [`rfam_display_label`](rules.md#rfam_display_label), decided).
- **Merged spellings** (`synonym_to_gene`: mouse `Tc`/`tc`, pig `PHGPx`/`PHGPX`, rhesus `ENV`/`env`, and some human lines): two genes with one string in two letter cases (rule [`spelling_per_edge`](rules.md#spelling_per_edge), decided).
- **A shared name the support cannot decide** (pig and rhesus `name_ambiguous_to_set`, a few `synonym_to_gene` and `name_old_to_current` lines): `best` returns one gene where BioMart shows equal support for the expected genes (rhesus: display names from VGNC, whose symbol column BioMart does not have).
- **Mouse strings in capitals** (lines of correction `capitals_mgi`): `d4c2dda` reads an all-capitals string as the synonym of another gene (rule [`single_case_symbols`](rules.md#single_case_symbols), decided); and one human `name_changed_gene` answer whose gene carries the name in a source the truth does not read.
- **One event whose version contradicts the tables** (human `retired_split`: `ENSG00000233776`, rule [`event_version`](rules.md#event_version), decided).
- **The truth's limits**: human answers that are genes the GTF of release 48 lacks while the core has them (`reverse_present`, `reverse_absent`), and copies reported apart at a release before 82 (`cross_assembly`, `reverse_absent`; [limits](#limits)).
- `nonexistent_version`: 1,000 per organism, by design ([the rule](#rule-version_newer_than_graph)).

## Limits

What the harness cannot check independently:

- The history truth is Ensembl's `stable_id_event`, the same table idtrack stores (read by independent code, and checked against REST for a sample): it tests idtrack's use of the history, not the history. Lineages that Ensembl's history dropped cannot be told from bridging errors except by place (the `locus` rule); places on two assemblies are compared through Ensembl's chain files where they exist (human, mouse, pig Sscrofa9 <-> 10.2; not pig Sscrofa10.2 <-> 11.1, rhesus, cynomolgus), and a mapped place may misjudge a gene the genome would allow in about 0.3 % (mouse) to 4 % (pig) of mapped places ([places across assemblies](#places-across-assemblies)).
- Copies before release 82 are told by Ensembl's assembly exceptions, not by the GTF (correction `copies_apart_early`, 15 above): a copy on a sequence that the exception tables of its release do not name is read as a reference gene.
- Genes the GTF of a release lacks (human 48 to 51, cynomolgus 112) are not in the truth's gene list of that release; `core_places` places them for the `locus` rule only.
- Names and external ids of old releases exist only where an archive BioMart still answers (pig: 75, 77, 80, 105-116). Sscrofa9 (pig 56-66) has none.
- The default strategy's choice among several right answers (e.g. the highest-scored successor of a split) is not scored: any non-empty subset of the right set is right for `best`.
- `nonexistent_version` encodes "a version that never existed has no answer"; rule `version_newer_than_graph` reverses it, so it is scored apart and is no part of the acceptance.
- BioMart's VGNC column is the VGNC id, not the symbol, so `VGNC Symbol` is not scored as a final database (VGNC's own sets give the symbols for `broad`); RFAM is not scored as a final database (idtrack returns the accession and the family label as two ids).
- Transcript-level and protein-level external ids are scored only through the gene they belong to.

## Run time

On `d4c2dda` (`run.json` of each run): the travel matrix, asked in 8 shards per organism, took 30.5 s of query time in all for pig, 94.8 s for mouse, 33.8 s for human, 30.5 s for rhesus and 7.8 s for cynomolgus; loading the graph took about 2.7 s per shard for pig, 10 s for mouse, 15 s for human, 1.6 to 4.4 s for rhesus and 6.5 s for cynomolgus (`<harness>/answers/d4c2dda/<organism>/travel/run.json`). The other kinds took 173.8 s of query time in all for pig, 277.0 s for mouse, 312.5 s for human, 139.0 s for rhesus and 108.4 s for cynomolgus (`<harness>/answers/d4c2dda/<organism>/kinds/run.json`). Transcript and translation ids, unknown versions and strings that are nothing are the slow kinds ([the cost model](methods.md#sizes-and-the-cost-model)). A job that holds a graph of the reference tree needs the memory the configuration gives the organism (`[jobs.memory_gb]`; defaults in `idtrack_reproducibility.config`); wall time depends on the queue. Merging and scoring a whole organism takes minutes. With `PYTHONHASHSEED=0` two runs of one tree on one graph give the same answers; family E measures determinism across seeds, processes, threads, orders and batches ([E's document](families/e.md)).
