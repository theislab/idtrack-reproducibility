# F0: the common machinery

F0 is what every benchmark family is built on: the query line, the query sets, the adapter that asks a line through any idtrack tree, the sharded runner, the scorer, the reports, the comparison of two runs, the explained paths, the classifier of wrong answers and the builder of the known-limitations rows. It is checked by asking the accuracy harness's own published sets ([the accuracy harness](../harness.md)) through it and requiring the harness's scorer's outcomes line by line. Its code is `idtrack_reproducibility.families` (the modules `lines`, `adapter`, `runner`, `scorer`, `report`, `compare`, `explain`, `causes`, `limitations`, `check_harness`, `common`); the design is in [the methods](../methods.md#f0-the-common-machinery).

## What it measures

F0 measures one thing of its own: that the machinery judges as the harness judges. The harness's published sets of all five organisms, asked through the adapter on both api generations of idtrack and scored by F0's scorer, must give the outcome, the reason and the answer that the harness's own `score.py` gave, line by line ([the check](#the-check-against-the-harnesss-scorer)). Once that holds, a family's numbers mean what the harness's numbers mean.

Asking the harness's sets through F0 also adds to the harness's tables what the families report: rates with Wilson and cluster-bootstrap intervals per kind and view, the distinct units behind the wrong answers, the latency of the calls, and a cause for every wrong answer. These are F0's results ([Results](#results)).

Two api generations are asked:

| generation | trees | how a line is asked |
| --- | --- | --- |
| `d4c2dda` | `d4c2dda` | `API(local_repository=...).build_graph(organism, snapshot_release)`, then `API.convert_identifier` once per view: a line scored under `best` and `all` costs two calls |
| `convert` | `71690ab` and later | `API.load(graph)`, then one `API.convert` call whose result holds both views |

The generation is read from the checkout (`common.generation`: `idtrack/api.py` or `idtrack/_api.py`).

## The query line

A query line is the accuracy harness's line (`qid`, `kind`, `id`, `from_release`, `to_release`, `final_database`, `strategy`, `rule`, `cmp`, `expect`, `broad`, `locus`, `note`, and the corrected judge's `locus_mapped`, `support`, `spellings`, `apart`, `revised_by`, `excluded`; [the accuracy harness](../harness.md)) plus these fields:

| field | meaning |
| --- | --- |
| `family` | the family (`astar`, `a`, `e`, ...; `harness` for the harness's own sets) |
| `stratum` | the group a report row is about; default: `kind` |
| `unit` | the cluster of the bootstrap (a gene id, a lineage component, a name, a dataset); default: `id` without its version |
| `strategy: both` | scored under `best` and under `all` (one `API.convert` call from `71690ab` on, two `convert_identifier` calls on `d4c2dda`); `best` or `all` score one view, as the harness's lines do |
| `from_database` | passed to the API when given (rule [`from_database`](../rules.md#from_database)) |
| `id_codec` | how `id` becomes the argument, for inputs that are not strings: `str` (default), `json` (null, numbers, lists, dicts), `bytes_hex`, `float_nan` |
| `expect_error` | the error class the documentation promises; `A\|B` for alternatives (one class per api generation) |
| `open` | a string: the truth leaves the line open; an answer is `undetermined` with this reason before every other rule |
| `relation` | with `rule: relation`: `{"op": "equal"\|"subset"\|"superset"\|"disjoint", "with": <qid>, "with_view": <view>}`, a relation between this line's answer and another line's instead of a truth |

Any other field a family needs is kept (in a Parquet set, in the JSON column `extra`). A qid is unique within a family and organism and is never reused for another question.

## Query sets

`lines.publish(family, organism, name, lines, description, generator, revises=None, judge=None, sources=None, fmt=None, manifest_extra=None, dry=False)` writes `<families>/<family>/queries/<organism>/<name>.parquet` (default; any iterable, streamed in chunks of 500,000 rows) or `<name>.jsonl.gz` (a list under a million lines), with `<name>.manifest.json`: the order number `seq`, `n`, the counts per stratum, the file's sha256, the time, the description, the generator with its sha256, `revises`, `judge`, `sources` and the family's own fields. Before the file takes its name the qids are checked to be distinct and, for a revision set, to be published in a set it revises; a failed check removes the file.

**A published set is never rewritten.** `publish` refuses an existing name, and published files are made read-only. A change of truth is a revision set holding only the changed lines under their published qids; the line of the latest set (highest `seq`) is the truth of a qid.

`lines.load(family, organism, sets=None, strata=None, kinds=None, shard=None, judge="revised", limit=None)` gives the latest line of every qid, the sha256 of every set read, and the counts of the lines left out (`excluded`). `family="harness"` reads the harness's sets where they are (`<harness>/queries/<organism>/`), in the harness's order and with its exclusions; `judge="published"` leaves out the revision sets of the corrected judge.

## The sets

F0 publishes no set of its own. It reads the harness's published sets in place (`family="harness"`, judge `revised`); the table of every set with its size, sha256 and date is in [the accuracy harness](../harness.md). F0's results read every set published (`run.json` of each scored run lists them with their sha256; lines counted with both views where a line has two):

| organism | sets read | lines |
| --- | --- | ---: |
| pig | `v1` to `v13` | 480,425 |
| mouse | `v1` to `v19` | 707,170 |
| human | `v1` to `v17` | 662,496 |
| rhesus | `v1` to `v12` | 465,481 |
| cynomolgus | `v1` to `v8` | 295,735 |
| all five | | 2,611,307 |

The check against the harness's scorer ([below](#the-check-against-the-harnesss-scorer)) was made on the sets of its day (mouse `v1` to `v15`, human `v1` to `v12`, cynomolgus `v1` to `v7`); F0's results are the same answers scored again with every set published since (the corrections `exceptions`, `exceptions_span` and `core_places`), and equal the harness's own current scoring kind by kind ([verification](../verification.md)).

## Truth

F0 holds no truth of its own: the expectation of a line is written in the line by the family's generator, from the one truth store `<truth>/<organism>/` (Ensembl's GTFs, core history tables, BioMart tables, chain files, assembly exceptions, the authorities' files; every file with its URL, size, md5 and time in `SOURCES.tsv`). Nothing of idtrack is read to make an expectation (rule [`truth_judges`](../rules.md#truth_judges)). The judge of a scoring is `revised` (the line of the latest set of every qid; the default) or `published` (the harness's sets without their revision sets).

## Rules

The scorer applies the harness's rules through the harness's own function and adds four of its own:

| rule | how F0 scores it |
| --- | --- |
| `set`, `set_exact`, `broad`, `locus`, `locus_mapped`, `apart`, `support`, `spellings`, `cmp` | the harness's `score.score_one`, called with the line's strategy set to the view scored ([the accuracy harness](../harness.md)) |
| `expect_error` | the class named (or a subclass: the answer's `error_mro`) raised: `expected_error`; another class, or an answer: `wrong` |
| `safe` | nothing, or a non-empty part of `expect`, is right (reason `nothing` or `recovered`); another gene is wrong; `recovered` in `report.tsv` counts the answers that named a gene |
| `open` | an answer is `undetermined` with the reason `open: ...`, before every other rule; a timeout or an error stays what it is (no answer was given) |
| `relation` | the line's answer is compared with the answer of the line it names (`equal`, `subset`, `superset`, `disjoint`), after every partition is scored |

Reading an answer is the harness's reading: on `d4c2dda` through `score.targets_of`; from `71690ab` on through `result.targets(view)`, with nothing for `not_found`, `unknown_version` and `no_conversion`, and, with a `final_database`, nothing for `no_target` or another database. A tree that renames a database or changes its result is adapted in `adapter.py`, in one place.

The harness's lines rest on idtrack's rules of reading a query and choosing an answer ([rules](../rules.md)): among them [`start_release`](../rules.md#start_release), [`unknown_version`](../rules.md#unknown_version), [`version_newer_than_graph`](../rules.md#version_newer_than_graph), [`own_id_first`](../rules.md#own_id_first), [`ties`](../rules.md#ties), [`copies_apart`](../rules.md#copies_apart), and the judge's rules [`judge_copies_apart`](../rules.md#judge_copies_apart), [`name_before_synonym`](../rules.md#name_before_synonym), [`support_ranks_shared_name`](../rules.md#support_ranks_shared_name) and [`judge_corrections`](../rules.md#judge_corrections).

## Scoring and outcomes

Outcomes: `right`, `wrong`, `undetermined` (with its reason), `timeout`, `error`, `expected_error`, `not_supported` (other tools). The rate is

    rate = (right + expected_error) / (right + expected_error + wrong + error)

with `undetermined` and `timeout` apart. A columnar fast path decides only what the harness's function surely calls right (the answer equal to `expect` after the line's `cmp`, on lines without `apart`, `spellings`, `expect_error` and `open`); every other row goes through the function itself.

A scoring writes into the run folder (or `--scores-to`): `outcomes/part_<p>_of_<P>.parquet` (one row per line and view; the query, expected and broad ids only on rows that are not right), `scores.tsv` (the harness's table: kind, variant, counts, rate, Wilson 95 %), `report.tsv`, `wrong.tsv.gz`, `undetermined.tsv.gz`, `errors.tsv`, `timeouts.tsv` and `run.json` (the sets with their sha256, the judge, the missing and excluded counts per stratum, the tree's commit and whether its checkout was modified, the graph's content digests, the load records).

`report.tsv` has one row per stratum and view (`*` = both views): `n`, `right`, `expected_error`, `wrong`, `undetermined`, `timeout`, `error`, `not_supported`, `missing`, `rate`, `wilson_low`, `wilson_high`, `boot_low`, `boot_high`, `units`, `units_wrong`, `units_error`, `recovered`, `s_p50`, `s_p95`, `s_p99`, `s_max`. The cluster bootstrap resamples the units of a stratum and view with replacement, 2,000 resamples, with the seed 20261118 combined with the group's name ([intervals](../methods.md#intervals)); `units_wrong` and `units_error` are the distinct units behind the wrong answers and the errors; the latency columns are seconds per call.

A large run is scored in partitions (`crc32(qid) % P`) by parallel jobs and merged; partitions give the same tables as one scoring. A partition holds about 3 million answers by default.

## Causes

`causes.py` gives every wrong answer a cause, read from the line, the answer and its explained path (`explain.py` asks the line again with `explain=True` on the tree that gave the answer). Each cause is a test; the first test that holds names the cause, and a row no test explains is `unexplained` and read by hand. Every cause has a class:

| class | meaning |
| --- | --- |
| a | idtrack is wrong under its own rules |
| b | idtrack follows a rule that the truth contradicts |
| c | the graph lacks what the truth has |
| d | the truth is wrong or the query invalid |
| e | the truth cannot decide |

A family registers its kinds (`register_kinds(history=, names=, databases=)`; an unregistered kind is read by its line: a `final_database` makes a database query, an Ensembl id a history query, anything else a name) and its own causes (`register(cause, cls, rule, text, test, before=None)`) in a module passed with `--plugin`. Outputs: `causes.tsv.gz` (one row per wrong answer) and `causes_summary.tsv` (stratum, cause, class, rule, answers, units); with `--und`, the same for the undetermined answers. `explain.py` takes at most `--per-unit` answers per unit and stratum (default: all).

`limitations.py` turns the causes into rows of the known-limitations table: a map gives each cause its limitation id, group, title, what it means and what a user can do; the counts are the run's. A cause without a map row is written with the title `UNMAPPED`, to be read and mapped.

## Running it

Every location comes from the configuration (`idtrack-repro.toml`, read from `$IDTRACK_REPRO_CONFIG` or the working directory): `<families>` and `<harness>` are its data locations; a tree's checkout is `[trees.<tree>] source`, its Python `[trees.<tree>] python`, its graph `[trees.<tree>.graphs] <organism>`. Jobs go through the configured runner (`[jobs] runner = "slurm"` or `"local"`; `jobs.submit`); with `--submit` the runner submits the shards in the tree's Python and the scoring in the package's Python.

```
# a family's run of one organism on one tree: n shard jobs, then a scoring job (or P partition jobs and a merge)
python -m idtrack_reproducibility.families.runner --family <f> --organism <o> \
    --clone <source of the tree> --graph <graph of the tree> \
    --out <families>/<f>/runs/<tree>/<o> --submit <n> --score [--score-parts <P>] \
    [--sets a,b] [--strata x,y] [--timeout 30] [--time 12:00:00]
# one process in the tree's Python; a smoke run of the first N lines of each stratum
<python of the tree> -m idtrack_reproducibility.families.runner ... --shard 0/1 [--limit 20]
# scoring (one job, or P partitions in parallel and a merge)
python -m idtrack_reproducibility.families.scorer --family <f> --organism <o> --run <run folder> [--judge revised|published]
python -m idtrack_reproducibility.families.scorer ... --parts <P> --part <p>
python -m idtrack_reproducibility.families.scorer ... --parts <P> --merge
# two scored runs: rates with intervals, regressions (exit 1 on right -> wrong or right -> error), every moved answer
python -m idtrack_reproducibility.families.compare <scored a> <scored b> [--moved moved.tsv] [--out changes.tsv]
# causes: explain the wrong answers on the tree that gave them, then classify
<python of the tree> -m idtrack_reproducibility.families.explain --family <f> --organism <o> \
    --clone <source of the tree> --graph <graph of the tree> --scored <run folder> [--per-unit 3]
python -m idtrack_reproducibility.families.causes --organism <o> --scored <run folder> \
    [--plugin src/idtrack_reproducibility/families/<f>/<causes module>.py]
# rows of the known-limitations table
python -m idtrack_reproducibility.families.limitations --family <f> --scored <run folder> [...] [--map <map .tsv>] --out <tsv>
# F0's check: a scored folder of the harness's sets against the harness's stored score.py runs
python -m idtrack_reproducibility.families.check_harness <run folder> <stored run> [<stored run>] [--out diff.tsv]
```

- **Shards**: a line belongs to shard `crc32(qid) % n`; a shard reads only its own lines and its own answered qids (the column `h` of sets and answers) and asks only what has no answer in the folder, whatever the sharding of earlier runs, so a resubmission continues. The graph file is linked into `<out>/repo/` (nothing is written beside the original) and loaded once per shard, then `gc.freeze()`; `PYTHONHASHSEED=0` (the runner restarts itself with it).
- **Budget**: `--timeout` seconds per call. `d4c2dda`: an alarm at the limit (the harness's 30 s). From `71690ab` on: `budget_seconds=timeout`, with an alarm at `timeout + 30` as a backstop. `SearchBudgetExceededError` and the alarm are the outcome `timeout`.
- **Answers**: `<out>/answers/shard_<i>_of_<n>.<k>.parquet`, a new part every 20,000 rows or 5 minutes, and `load_<i>_of_<n>.json` (the api generation, the idtrack file loaded, the Python, the load time, the files written beside the graph (must be none), the graph's content digest). One row per line and view: `qid`, `h`, `view`, `outcome` (`answer`, `timeout`, `error`), `got` (the ids, sorted), `apart` (copies reported apart; none when the tree has no such list), `status` (`converted`, `tie`, `no_target`, `no_conversion`, `not_found`, `unknown_version`; derived from the flags on `d4c2dda`), `match`, `tie`, `from_release` (used), `fallback`, `final_database`, `flags`, `error_type`, `error_mro`, `error`, `traceback`, `seconds` (of the call that gave the view), `calls`, and with `explain` the `path`.
- **Memory**: a job that holds a graph gets the configuration's `[jobs.memory_gb]` for the organism (defaults: human 90 GB, mouse 50 GB, pig and rhesus 24 GB, cynomolgus 20 GB).

## The check against the harness's scorer

The harness's published sets of all five organisms (2,611,307 lines: pig 480,425, mouse 707,170, human 662,496, rhesus 465,481, cynomolgus 295,735; the `v1` to `v<n>` of [The sets](#the-sets)), asked through the adapter on `d4c2dda` and on `71690ab` with the reference graphs, scored by F0's scorer under the judge `revised`, and compared by `check_harness` with the harness's stored `score.py` runs of `d4c2dda` on the same sets (its kinds and its travel matrix):

| tree asked through F0 | lines | differences in outcome, reason or answer |
| --- | ---: | ---: |
| `d4c2dda` | 2,611,307 | 0 |
| `71690ab` | 2,611,307 | 0 |

Pig's `scores.tsv` of F0 equals the harness's `scores.tsv` row by row, and `compare` of the `d4c2dda` run with the `71690ab` run moves no answer: `71690ab` is answer-identical to `d4c2dda` on every line of the harness. Every wrong answer of the `d4c2dda` runs has a cause (17,742 answers over the five organisms, none `unexplained`; [Results](#results)).

## Reproducing from scratch

From an empty data root, with the configuration naming the data root, the trees `d4c2dda` and `71690ab` (their checkouts of github.com/theislab/idtrack, their Pythons and their graphs) and the job runner:

1. **Fetch the truth** of each organism into `<truth>/<organism>/` (every file recorded in `SOURCES.tsv`): `python -m idtrack_reproducibility.harness.fetch_gtf --organism <o>`; `python -m idtrack_reproducibility.harness.fetch_tables --organism <o> core`, `... biomart --releases <releases>`, `... vgnc`, `... chains`, `... exceptions`, `... grc_alignments`, `... core_places --releases <releases>`; `python -m idtrack_reproducibility.harness.fetch_rest --organism <o>` ([the accuracy harness](../harness.md)).
2. **Publish the sets**: the harness's sets with `python -m idtrack_reproducibility.harness.make_queries` (each set, then the revision sets of the corrected judge with `--revise`), in the harness's order. F0 publishes none.
3. **Build or place the graphs** each tree reads, as configured (`[trees.<tree>.graphs]`).
4. **Run** the harness's sets through F0 on each tree: `python -m idtrack_reproducibility.families.runner --family harness --organism <o> --clone <source> --graph <graph> --out <families>/f0/runs/check_<tree>/<o> --submit <n> --score`.
5. **Score** (the runner's scoring job, or `python -m idtrack_reproducibility.families.scorer --family harness --organism <o> --run <families>/f0/runs/check_<tree>/<o>`), and **check** against the harness's own scoring of the same tree: `python -m idtrack_reproducibility.harness.score ...` into `<harness>/runs/<run>/<o>`, then `python -m idtrack_reproducibility.families.check_harness <families>/f0/runs/check_<tree>/<o> <harness>/runs/<run>/<o> [<harness>/runs/<travel run>/<o>]` (exit 0: no difference).
6. **Compare** the trees: `python -m idtrack_reproducibility.families.compare <families>/f0/runs/check_d4c2dda/<o> <families>/f0/runs/check_71690ab/<o>`.
7. **Classify**: `explain` on each tree's run (in the tree's Python), then `causes`.
8. **Limitations**: `python -m idtrack_reproducibility.families.limitations --family harness --scored <families>/f0/runs/check_d4c2dda/<o> ... --out <tsv>`.
9. **Results**: `idtrack-repro results` writes `results/f0/<tree>/<organism>/` (`report.tsv`, `scores.tsv`, `causes_summary.tsv`), the known-limitations table, `results/index.tsv` and `results/provenance.tsv` from the runs registered in `results.toml`.
